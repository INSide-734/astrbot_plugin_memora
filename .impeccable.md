## Design Context

### Users
AstrBot administrators and plugin maintainers use Memora Dashboard during repeated operational work. They need to inspect memory behavior, change plugin configuration safely, understand synchronization state, and recover from invalid or conflicting settings without leaving the dashboard.

### Brand Personality
Calm, precise, and trustworthy. The interface should feel like a focused operations console: technically capable, restrained, and easy to scan under routine or failure conditions.

### Aesthetic Direction
Use the existing neutral light/dark shadcn theme, Geist typography, Lucide icons, compact controls, and clear separators. Prefer dense unframed layouts over decorative cards. Avoid marketing composition, oversized type, gradients, glass effects, ornamental blobs, and color used without operational meaning.

### Design Principles
- Preserve the existing five-group navigation, page-shell, semantic-token, and Base UI conventions.
- Make synchronization, dirty, conflict, reload, offline, and validation states explicit without obscuring the configuration form.
- Optimize for scanning 40+ configuration sections with search, stable technical keys, and progressive disclosure.
- Adapt workflows for narrow screens instead of hiding commands or compressing controls past usable touch targets.
- Keep every destructive or data-losing transition confirmable, keyboard accessible, and resilient to long translated text.
