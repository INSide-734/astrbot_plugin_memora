2. **第一人称边界**: 可以用第一人称组织叙述，但不能把助手的行为、建议、推断、自我描述或环境描述写成群成员事实。
3. **识别他人**: 其他 `[昵称 |` 消息必须使用前缀中的具体昵称；若末尾提供稳定参与者身份约束，则使用“当前名称（稳定标识）”。禁止用“用户”“某人”“群成员”等泛化词代替具体主体。
4. **稳定标识来源**: 示例中的 `QQ:123456` 和 `QQ官方:0123456789abcdef01234567:A1B2C3D4` 仅用于展示协议标签格式，禁止复制到实际结果。实际稳定标识只能使用末尾“稳定参与者身份约束”中明确提供的完整值；未提供稳定参与者身份约束时，不得根据昵称、消息前缀中的普通账号字段或示例自行猜测、构造任何协议身份标识。
5. **忽略系统标识**: 含“Error”“Warning”等系统标记的内容不属于对话事实；群聊应包含所有群成员消息，并严格遵循系统指令的话题分割要求。
6. **用户证据优先**: summary、content、key_facts 只能记录当前窗口用户消息直接支持的稳定事实、明确计划、偏好、决定、群体规范，或经用户明确确认的关系事实。

# 任务要求
以**第一人称**回顾上述群聊对话，用**符合你人格设定的语气和视角**描述记忆；第一人称只改变叙述方式，不改变事实来源。重点关注：

1. **讨论主题**: 群里讨论了什么（topics 最多 5 个）。
2. **参与者和发言**: 记录哪些群成员明确说了什么；助手回复只用于理解上下文，未经用户确认不得写入可写字段。
3. **关键信息**: 重要的事实、决策、计划和群体规范，必须关联到具体昵称；存在稳定参与者身份约束时使用“当前名称（稳定标识）”。
4. **群体氛围**: 整体互动的情感基调 → sentiment（家庭群/朋友群的基线不能替代实际证据）。
5. **情感标签**: 群聊氛围的情感色彩 → emotion_tags。
6. **因果关系**: 仅记录对话中明确且由用户消息支持的因果链 → causal_relations。
7. **关系动态**: 仅记录群成员明确表达或确认的亲近、摩擦、信任、默契或联盟变化，不凭助手推测。
8. **群体角色**: 仅记录用户消息支持的组织者、活跃分子或关键发言角色，不把助手自我描述当作群体角色。
9. **计划与规范**: 群里由用户形成的约定、决定、时间安排和规则。涉及全员或多数人的计划 importance ≥ 0.7。

# 输出格式
必须输出标准 JSON，使用 `memories` 数组格式，每个元素是一个独立话题的记忆：

```json
{
  "memories": [
    {
      "summary": "我记得具体昵称明确表达的第一个稳定事实（第一人称叙述）",
      "topics": ["讨论主题1"],
      "key_facts": ["具体昵称+用户明确表达的事实"],
      "participants": ["发言者稳定标签或具体昵称"],
      "sentiment": "positive",
      "importance": 0.7,
      "emotion_tags": [],
      "causal_relations": [],
      "source_refs": [{"message_index": 0, "start": 0, "end": 12}]
    }
  ]
}
```

## 字段说明
- `summary`（必填）: 非空记忆的第一人称摘要；可以用第一人称作叙述框架，但每个事实必须由当前窗口用户消息支持。
- `topics`（必填，最多 5 项）: 具体的讨论主题，不要把助手建议或环境自述写成主题事实。
- `key_facts`（必填，最多 5 项）: 只提取值得长期记住、由用户消息支持的事实、明确计划、偏好、决定、群体规范或已确认关系；默认使用“具体昵称+事实内容”，有稳定身份约束时使用“当前名称（稳定标识）+事实内容”。
- `participants`（必填）: 有稳定参与者身份约束时只列出约束中的 user 稳定标签，不加入 Bot；没有约束时使用消息中可见的具体昵称。participants 仅用于内容理解，最终身份元数据由系统确定。
- `source_refs`（必填）: 每条记忆引用当前窗口中支持该记忆的用户消息正文区间；不要用助手消息作为用户证据。
- **禁止写入**: 助手建议、推断、工具结果、环境/能力/配置/运行状态自述，以及未获用户确认的助手回复，不得进入 `summary`、`content` 或 `key_facts`。
- 跳过纯寒暄、纯应答、无信息量闲聊、没有具体原因的短暂情绪和无实质内容的感叹。

## 无稳定事实时的输出规则
- 总结触发只代表进行一次总结尝试，不代表必须生成长期记忆。
- 如果对话只有寒暄、纯应答、无信息量闲聊或短暂情绪，没有值得长期记住的稳定用户事实，必须输出 `{"memories": []}`。
- 不得使用对话摘录、默认摘要、人格设定、助手行为或环境描述填充候选。
- 只有存在明确、可由当前用户消息支持且值得长期保留的事实、偏好、计划、关系、决定或群体规范时，才输出 `memories` 条目。
- 没有用户确认的助手建议，即使与群聊主题相关，也必须从可写字段中排除。
- `sentiment` 必须为 `positive`、`neutral` 或 `negative`；无明显情感时使用 `neutral`。
- `importance` 必须在 0.0 到 1.0 之间；群体计划、规范或承诺通常至少为 0.7。
- `emotion_tags` 最多 3 个；没有明显情感时输出空数组 `[]`。
- `causal_relations` 最多 3 个；只有存在明确因果逻辑且因果双方均有用户证据时填写，否则输出空数组 `[]`。

## 重要性评分标准（0.0-1.0）
- **0.9-1.0**: 重要群体决策、形成共识或计划、群体规范、长期安排；个人重大信息即使只有一人表达也可高重要。
- **0.7-0.8**: 有价值的讨论、多人参与、有明确结论、家庭事务协调或个人近况分享。
- **0.5-0.6**: 日常讨论、中等参与度、一般信息交流。
- **0.3-0.4**: 简单闲聊、少数人参与、无实质决策。
- **0.0-0.2**: 无意义灌水、单人刷屏、纯系统消息或纯寒暄；此类对话必须输出空数组。
