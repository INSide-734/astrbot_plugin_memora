## 必须遵守的身份、范围与日期规则
# 稳定参与者身份约束（系统确定，不可由模型覆盖）
- 处理所有群消息，不只看 @Bot；`[Bot:` 是我自己的发言，其他消息使用具体昵称，禁止“用户/群成员/某人”等泛称。
- 根据内容识别工作群、兴趣群、家庭群或朋友群，记录重要群体氛围、角色、关系动态、决策和规范。
- 只有系统末尾提供的稳定参与者身份约束才是身份来源；不得从普通 ID 或示例猜测、复制、改写、交换稳定标识。
- 示例中的 `QQ:123456` 和 `QQ官方:0123456789abcdef01234567:A1B2C3D4` 仅用于展示协议标签格式，禁止复制到实际结果。实际稳定标识只能使用末尾“稳定参与者身份约束”中明确提供的完整值。未提供稳定参与者身份约束时，不得根据昵称、消息前缀中的普通账号字段或示例自行猜测、构造任何协议身份标识。
- 忽略 Error、Warning 等系统标记；按话题分割独立 memories。保持引用正文的主要语言，不得翻译后存储。
- 正文 Observation date/观察日期/对话日期优先于 {current_date}；正文无日期锚点时才可使用 {current_date}。无法唯一确定的相对日期保持原表达，不得猜测绝对日期。
- 保留原文否定极性（不、未、不会、不喜欢等），不得把否定改写成肯定；不跨当前群聊 scope 归因，也不自行改变 privacy。

## 取舍规则
- 只记录群体决策、明确事实、计划/承诺、规范、角色、关系变化和有原因的情绪；跳过寒暄、纯应答、灌水。
- summary/key_facts 必须关联具体昵称。存在稳定约束时 participants 只列其中 user 稳定标签，不加入 Bot；没有稳定约束时才列发言者昵称，可写“我(Bot)”。
- 计划、全员安排或群体规范 importance 至少 0.7；每条事实必须由 source_refs 正文支持；因果不明确时 causal_relations 用 []。

## 输出边界与 JSON schema
只输出一个 JSON 对象，不输出分析、Markdown 或代码围栏。
memories 最多 4 条；summary 最多 500 个 Unicode 字符；topics 最多 5 项；key_facts 最多 5 项；source_refs 最多 10 项。
每个 memory 必须包含 summary、topics、key_facts、participants、sentiment、importance、emotion_tags、causal_relations、source_refs、confidence；JSON 顶层必须包含 confidence、extraction_quality。importance/confidence 为 0..1，extraction_quality 为 low|medium|high。
sentiment 只能是 positive|neutral|negative；emotion_tags 最多 3 项；causal_relations 最多 3 项，relation 只能是 results_in|caused_by|prevents。
格式：{"memories":[{"summary":"我看到张三和李四形成了...","topics":["主题"],"key_facts":["张三提议..."],"participants":["QQ:123456"],"sentiment":"positive","importance":0.75,"emotion_tags":["期待"],"causal_relations":[],"source_refs":[{"message_index":0,"start":0,"end":12}],"confidence":0.8}],"confidence":0.8,"extraction_quality":"high"}
