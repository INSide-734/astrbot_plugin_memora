## ⚠️ 核心规则（必须遵守）
1. **识别自己**: 以 `[Bot:` 开头的消息是你自己的发言，必须用第一人称描述
2. **识别他人**: 其他 `[昵称 |` 开头的消息是群成员的发言，**必须使用消息前缀中的具体昵称**（如"张三"）；若末尾提供稳定参与者身份约束，则使用“当前名称（稳定标识）”指代，名称变化不代表换了用户。**禁止**使用"用户"、"某用户"、"群成员"、"某人"等泛化词汇

6. **话题分割**: 请严格遵循系统指令中的话题分割要求，将独立话题输出为 `memories` 数组的独立条目

# 任务要求
以**第一人称**回顾上述群聊对话，用**符合你人格设定的语气和视角**来描述记忆。重点关注：

1. **讨论主题**: 群里讨论了什么（topics 最多 5 个）
2. **参与者和发言**: 谁说了什么，你自己（Bot）的回复内容
3. **关键信息**: 重要的事实、决策、计划、群体规范，**必须关联到具体昵称**
4. **群体氛围**: 整体互动的情感基调 → sentiment（家庭群/朋友群天然偏 positive 基线）
5. **情感标签**: 群聊氛围的情感色彩 → emotion_tags（注意：家庭群常见"关心""幸福"，朋友群常见"开心""搞笑"，工作群常见"严肃""好奇"）
6. **因果关系**: 对话中明确的因果链 → causal_relations
7. **关系动态**: 群成员之间的互动——谁与谁更亲近、是否有小团体信号、是否有摩擦或联盟变化。在 key_facts 中标注关系线索
8. **群体角色**: 成员在群中的角色——谁是组织者、谁是活跃分子、谁是关键时发声的人。帮助理解群体权力结构
9. **计划与规范**: 群里形成的约定、决策、时间安排、不成文规则。涉及全员或多数人的计划 importance ≥ 0.7

# 输出格式
必须输出标准 JSON，使用 `memories` 数组格式，每个元素是一个独立话题的记忆：

```json
{
  "memories": [
    {
      "summary": "我观察到的第一个话题摘要（第一人称，使用具体昵称，体现人格特点）",
      "topics": ["讨论主题1", "主题2"],
      "key_facts": ["具体昵称+关键事实1", "事实2"],
      "participants": ["发言者昵称1", "发言者昵称2"],
      "sentiment": "positive|neutral|negative",
      "importance": 0.7,
      "emotion_tags": ["开心", "热烈"],
      "causal_relations": [
        {"cause": "原因描述", "effect": "结果描述", "relation": "results_in|caused_by|prevents"}
      ]
    },
    {
      "summary": "第二个话题摘要（如果有的话）",
      "topics": ["主题3"],
      "key_facts": ["事实3"],
      "participants": ["发言者昵称3"],
      "sentiment": "neutral",
      "importance": 0.5,
      "emotion_tags": [],
      "causal_relations": []
    }
  ]
}
```

**字段说明**:
- `summary` (必填): 第一人称摘要，使用具体昵称，体现你的人格语气。确保覆盖对话中的所有关键决策和计划
- `topics` (必填, 最多5个): 讨论的核心主题，应具体而非泛化（如"周末团建滑雪计划"而非"讨论"）
- `key_facts` (必填, 最多5个): **仅提取值得长期记住**的重要事实，"具体昵称+事实内容"格式，如"张三提议明天去滑雪"。
  **跳过以下内容（不要放入 key_facts）**：
  - 纯寒暄/问候（"早"、"晚安"、"吃了吗"、"在吗"）
  - 纯应答（"好的"、"收到"、"知道了"、"+1"、"👌"）
  - 无信息量的闲聊（"哈哈哈"、"今天天气不错"、"我吃饭了"）
  - 转瞬即逝的情绪表达（不含具体原因的"开心"、"难过"、"烦"）
  - 无实质内容的单句感叹
- `participants` (必填): 默认列出所有发言者的具体昵称；存在稳定参与者身份约束时使用约束中的稳定标识，最终持久化值由系统确定
- `sentiment` (必填): 群体整体氛围 — positive（积极/热烈/温馨）、neutral（中性/日常）、negative（消极/冲突）
- `importance` (必填, 0.0-1.0): 见下方评分标准
- `emotion_tags` (推荐, 最多3个): 从以下候选中选择最能描述群聊氛围的 1-3 个标签。若对话无明显情感色彩（纯事务性讨论），可输出空数组 `[]`
  - 候选词: 开心、热烈、温馨、关心、好奇、担忧、焦虑、困惑、失望、生气、期待、惊讶、放松、感动、幸福、怀念、搞笑、严肃、无聊、撒娇、唠叨、心疼、亲密、默契、热闹、尊重、感慨
- `causal_relations` (可选, 最多3个): 对话中的因果关系链。只在存在**明确**因果逻辑时输出，无因果关系则输出空数组 `[]`
  - `relation` 类型: `results_in`（A导致B）、`caused_by`（A因为B）、`prevents`（A避免/阻止了B）
  - 示例: `{"cause": "张三提议周末团建", "effect": "大家开始讨论地点和时间", "relation": "results_in"}`

# 重要性评分标准 (0.0-1.0)
- **0.9-1.0**: 重要群体决策、全员参与、形成共识或计划、群体规范、长期安排；**个人重大信息**（健康状况变化、重要人生事件、强烈情感倾诉）——即使只有 1 人说也高重要
- **0.7-0.8**: 有价值的讨论、多人参与、有明确结论、群体情感表达强烈；**家庭事务协调**（聚餐安排、照顾分工）或**个人近况分享**（体检结果、出行计划、心情状态）
- **0.5-0.6**: 日常讨论、中等参与度、一般信息交流；**日常问候**、随手分享（发照片、报平安、闲聊家常）
- **0.3-0.4**: 简单闲聊、少数人参与、无实质决策；**纯应答**（"好的""收到""知道了"）
- **0.0-0.2**: 无意义灌水、单人刷屏、纯系统消息、纯寒暄 — **此类对话不应产生 key_facts，输出空数组 []**

**评分提示**: 参与人数不是唯一标准——**内容的情感密度和个人相关性**同样重要。家庭群中奶奶说"头有点晕"，即使只有她一个人说话，importance 至少 0.7。涉及群决策、活动安排、资源分配的信息应提高评分。若 emotion_tags 包含强烈情感（如"热烈"、"感动"、"生气"、"心疼"），importance 至少 0.6。群体形成明确约定或规则时，importance ≥ 0.75。涉及多人关系动态变化（如化解误会、新成员融入），importance ≥ 0.7。
