# 隐私安全诊断报告设计

## 目的与威胁模型

问题报告需要帮助定位插件的初始化、召回、反思、存储和关闭故障，但调试输出所在的 AstrBot 日志与插件数据目录可能被管理员导出、备份或共享。对话正文、查询、Prompt、模型回复、记忆正文、用户/群组/会话/消息/记忆标识、Provider 配置和异常消息都视为敏感数据，诊断功能必须默认不能接触这些内容。

## 安全边界

业务调用点只传递固定的事件、阶段、原因码、状态、能力枚举和非负标量；`DebugReporter` 是最后一道拒绝边界，负责校验事件/字段/枚举、生成随机操作关联码、清洗异常摘要并同时写入控制台与受限轮转 JSONL。文件 sink 失败只停用文件输出，不得影响聊天主链路。诊断文件属于插件数据目录，只应通过 AstrBot 管理员问题报告流程读取。

## 安全决策

- 复用现有顶层 `debug` 配置，不增加第二套开关或默认打开日志。
- 事件和字段采用 allowlist；`component`、`stage`、`reason_code`、`capability` 还必须属于固定值集合。未知事件、字段或值整条拒绝，避免依赖事后脱敏。
- 数值只允许有限、非负且有界的耗时、计数、预算和队列深度；布尔值、负数和无限值拒绝。
- 异常只保留类型与插件内模块/函数/行号，不读取异常消息、参数、绝对路径或完整 traceback。
- 只保存低基数计数和状态。初始化、存储、召回、注入、反思和关闭阶段使用固定阶段事件；存储幂等重试明确区分新写入、失败与跳过项。
- 操作关联码为短期随机值，不使用用户、会话、消息或记忆标识，且不写入 URL、Prompt、决策记录或业务数据。
- JSONL 使用单文件加两个备份、单文件 5 MB 上限；关闭调试后关闭文件句柄，不创建空目录。

## 已知风险与接受范围

耗时、计数、固定函数名和组件就绪状态仍可能暴露粗粒度的运行活动与内部结构，这是问题报告所需的最小运维信息。诊断日志仍位于 AstrBot 管理员信任边界内，不应发送给普通聊天用户或未经审查的第三方。安全扫描器对非安全随机数和固定 SQL 标识符可能产生误报；本设计只接受经过数据流复核、且不涉及凭据或用户可控敏感内容的既有告警。

## 变更历史

### 2026-07-31 - 增加检索路由降级标量

**变更内容**：召回性能样本新增文档、图、Atom 三路固定布尔降级标记和整次路由中止标记。

**变更理由**：仅有阶段耗时无法区分完整成功、单路降级和达到阈值后的整次失败，运维指标需要安全且可聚合的状态信号。

**影响范围**：`RouteExecutionCoordinator`、`DualRouteRetriever`、请求局部计时、`PerfTracker` 样本与指标 API。

**决策依据**：不记录路由列表、查询、正文或业务 ID，只发出值为真的固定布尔标记；不存在标记即表示该状态未发生。

### 2026-07-20 - 扩展生命周期诊断

**变更内容**：增加存储/演化计数、Provider 等待、组件就绪、启动备份/恢复、运行时发布和逐步关闭事件，并收紧固定字段值校验。

**变更理由**：用户问题报告需要在不暴露隐私的前提下定位初始化、持久化和关闭阶段的降级与耗时。

**影响范围**：`core/features/observability/`、`PluginInitializer`、`MemoraPlugin`、`EventHandler`、`ReflectionHandler` 及对应 pytest 契约。

**决策依据**：继续复用现有 `debug` 开关、事件 allowlist 和 JSONL sink；只增加低基数标量与固定枚举，不记录业务正文或身份标识。
