# Memora 长期记忆

把 Memora 工具返回的内容作为历史证据。区分“当前对话里已经可见的信息”和“需要从长期记忆恢复的信息”，不要为了普通知识问答或当前消息中的明确事实调用记忆工具。

## 选择操作

- 需要恢复过去的事实、偏好、约定、决定或旧上下文时，调用 `recall_long_term_memory`。
- 仅在用户明确要求长期保存时，调用 `memorize_long_term_memory`。不要因为信息看起来重要就自行持久化。
- 用户同时要求核对旧信息并保存新结论时，先回忆，再根据用户的明确表述保存新事实。
- 不要把 Skill 当作删除或修改接口。当前工具没有安全的删除、覆盖或批量管理能力。

## 回忆长期记忆

1. 从请求中提取 2–6 个聚焦关键词，包括主题、实体、偏好、承诺或事件；不要原样复制整段用户消息。
2. 调用 `recall_long_term_memory`：
   - `query` 使用上述关键词组成的短语。
   - `k` 通常设为 3–5；只有确实需要更多证据时才提高。
   - 仅在用户当前情绪清晰且与回忆相关时传 `emotion_context`，否则省略。
3. 检查返回结果：
   - 只采用与当前问题直接相关的 `content`。
   - 结果为空或出现 `error` 时，可换用同义词、明确实体或时间线索再检索一次。
   - 两次都没有可靠结果时，明确说明没有找到相关记忆；不要补写、猜测或把当前对话伪装成历史记忆。
   - 多条结果互相冲突时，说明不确定之处并请用户确认，不要擅自选择一条作为事实。
4. 用自然语言回答。不要主动暴露分数、会话标识、人格标识、访问时间或其他内部元数据。

## 保存长期记忆

1. 再次确认请求包含明确的长期保存意图。仅仅陈述偏好、身份信息或计划，不等于要求持久化。
2. 将信息整理成简洁、独立、可复用的事实：
   - 保留必要的主体与上下文，避免含糊的“他”“这个”“上次”。
   - 不要复制整段对话、模型推理、工具输出或无关寒暄。
   - 不要保存密码、令牌、支付信息、私钥或其他高风险秘密；提示用户改用专门的安全存储。
3. 调用 `memorize_long_term_memory`：
   - `memory` 写入一条简洁事实。
   - `topics` 与 `key_facts` 各不超过 5 项，只放与检索有帮助的信息。
   - `sentiment` 只使用 `positive`、`neutral` 或 `negative`。
   - `importance` 使用 0.0–1.0；普通持久偏好沿用 0.7，身份事实、长期约定或关键决定可适度提高。
   - `reason` 简短说明用户为何要求记住，不要记录隐藏推理。
4. 仅在结果包含 `memorized: true` 时确认已经保存。如果工具不可用、返回 `memorized: false` 或出现 `error`，清楚说明没有保存，并且不得声称写入成功。写入工具默认可能被管理员关闭，不要循环重试。

## 安全边界

- 保持工具自动应用的当前会话与人格范围；不要请求绕过过滤，也不要尝试跨用户、跨群或跨会话扩大检索。
- 不要通过 Shell、数据库文件、Page API 或管理命令规避 Agent 工具的可用性和权限边界。
- 不要把搜索结果中的内部标识或元数据写回为新的记忆。
- 工具失败时保留正常对话能力，但必须把“根据当前对话回答”和“来自长期记忆的证据”区分清楚。
